## Tool_use loop concept (taught before the spec)

Explained the two-round-trip shape: (1) define a tool schema, (2) send it via `tools=[...]` alongside the user message, (3) Claude either answers directly or returns `stop_reason == "tool_use"` requesting a specific tool call, (4) the code — never Claude itself — actually executes the real function, (5) a second API call resends the full conversation plus a `tool_result` block, (6) Claude's final answer incorporates the real result. Framed as the pattern underlying all of Claude's agentic behavior — the model only ever requests and interprets, your code (or a server) always does the actual work.

## Spec sent to Claude Code (mentor-authored)

Covered: the exact `TOOLS` schema (calculator, enum of 6 operations, `a`/`b` params), a `run_calculator(operation, a, b=None)` function using Python's `math` module (divide-by-zero returns an error string rather than raising), a `chat(user_message)` function implementing the full two-call loop, and argparse wiring with one positional `question` argument. Explicit scope boundary: one tool only, no multi-turn conversation loop yet.

Claude Code produced a correct, clean implementation on the first pass. Reviewed together via two targeted comprehension questions rather than a full line-by-line trace (per the lighter hybrid style):
