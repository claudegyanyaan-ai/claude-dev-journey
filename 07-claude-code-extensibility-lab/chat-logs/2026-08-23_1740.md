## Build steps 1–4 and a real discovery

- **Step 1** — `.claude/agents/code-explainer.md`: a read-only
  (`Read, Grep, Glob` only, no `Write`/`Edit`/`Bash`) subagent whose
  `description` field doubles as its auto-delegation trigger.
- **Step 2** — `.claude/commands/update-logs.md`: the `/update-logs`
  slash command itself, with `disable-model-invocation: true` (a
  file-writing command should only ever be triggered by the user typing
  it, never by Claude on its own) and `allowed-tools: Read, Write, Edit,
  Glob` — deliberately no `Bash`, since `Glob`'s mtime sorting plus the
  date already in context was enough to find the active project folder.
- **Step 3** — the push-reminder hook: `.claude/hooks/post-commit-push-reminder.sh`
  plus `.claude/settings.json` wiring it to `PostToolUse` on the `Bash`
  matcher, narrowed further by `if: "Bash(git commit *)"`. The script adds
  a second, redundant check of the command string itself (defense in
  depth) before checking `git rev-list --count '@{u}..HEAD'` and printing
  a non-blocking `{"additionalContext": "..."}` reminder only when the
  branch is actually ahead — failing open (silent `exit 0`) if `git` is
  missing or there's no upstream.
- **Step 4** — this project's own `README.md` (What it does / Setup /
  Usage / How it works / Known limitations / Demonstration) and a
  `PROGRESS.md` stub, left pending until close-out.

**Real discovery made while testing, not just designed for**: attempting
to force-invoke `code-explainer` via the `Agent` tool immediately after
creating it failed — `Agent type 'code-explainer' not found`, listing only
the fixed set of agents available at session start. Same thing happened
moments later with `/update-logs` (`Unknown command`). Root cause,
confirmed by reasoning through the mechanism rather than guessing: Claude
Code reads `.claude/agents/`, `.claude/commands/`, and
`.claude/settings.json` once at session startup, not continuously — a file
created mid-session is invisible to that session no matter how long it
keeps running. This became the single most useful practical lesson of the
project, documented explicitly in the README's "Known limitations" and
"Setup" sections, and confirmed via the close-out conceptual check.

A separate detour mid-build: the user asked for an explanation of MCP
(Project 6's protocol), unprompted by any code-writing step. Answered
directly from the mentor persona rather than delegating to
`code-explainer`, since it read as a concept question ("what is this
protocol and why") rather than a code-reading request — which itself
surfaced the fuzzy boundary between "mentor explains a concept" and
"subagent explains code" as a real, worth-naming limitation.
