### Commit 1 — certification target dropped, goal reframed to broad literacy

`f0b3775` — decided explicitly via `AskUserQuestion` after the user's
Project 6 checkpoint-quiz answers surfaced a real conflict: the stated
goal was still "pass the Claude Certified Developer – Foundations exam,"
but the user's actual behavior and preferences pointed at wanting broad,
practical understanding of what Claude Code builds and why, not deep
hands-on coding fluency or a formal certification.

Changes made consistently across `CLAUDE.md`, `PLAN.md`, `PROGRESS.md`,
and `progress-dashboard.html`:
- **Goal rewritten**: broad, practical literacy in directing Claude to
  build real projects — understanding what gets built, why it's shaped
  that way, and how to reason about tradeoffs — explicitly **not** aiming
  at deep coding fluency or any certification.
- **Default workflow flipped**: Claude Code now writes the code by
  default (user reviews the diff, tests it, gets every non-obvious line
  explained), replacing the original "user writes, Claude coaches"
  default — direct consequence of dropping the fluency target. The user
  can still opt back into typing any given piece themselves.
- **Close-out checks reframed**: from line-by-line code-tracing checkpoint
  quizzes to conceptual questions about a project's shape and reasoning.
- **PLAN.md's "cert domain" column** renamed to "concept area" throughout
  the project ladder; PART 6 rewritten from an exam-readiness checklist
  to a broad-literacy checklist; a explicit note added telling future
  sessions to stop and check rather than assume the old exam framing
  still applies if it ever resurfaces.

### Commit 2 — "Claude Code in Action" course concepts woven into Projects 7–15

`da5ea38` — the user reviewed Anthropic's free "Claude Code in Action"
course (`anthropic.skilljar.com/claude-code-in-action`, aimed at teams
moving from one-off prompts to longer, less-supervised, team-wide
workflows) and asked to fold its ideas into the existing ladder rather
than bolt on a separate track — a natural fit given the shared 3-person
GitHub repo this project ladder already runs on. Noted explicitly: a
Coursera listing with the same title is the beginner "Claude Code 101"
content already completed elsewhere — not the same material, don't
conflate them.

Nine operational concepts from the course — steering long sessions, a
CLAUDE.md Claude actually follows, verification skills, permission modes,
hooks, routines/headless mode, GitHub Actions and code review, verifying
unsupervised runs, and plugins — were mapped onto Projects 7–15 at their
most natural fit point via a new "Also covers" column in `PLAN.md`'s
tier tables, rather than run as a separate curriculum thread. Project 7
specifically now also covers: steering long sessions (Plan Mode as a
repeatable habit, directed compaction, the rewind menu), writing a lean
CLAUDE.md that Claude actually follows, and permission modes (matching
mode to exploratory vs. routine vs. high-trust work). Three new checklist
items were added to PART 6, and a ground rule was added stating this
mapping is a guide, not a hard requirement — if a project's natural flow
doesn't need one of the woven-in concepts, that's fine to say rather than
forcing it in. The course's own exam-relevance framing was stripped out
throughout, consistent with Commit 1.
