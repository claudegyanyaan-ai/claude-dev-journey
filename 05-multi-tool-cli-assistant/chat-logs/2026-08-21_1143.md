  since regression testing specifically means re-testing after code

## Comprehension check (checkpoint quiz style)

1. Asked what would break if Project 4's fixed two-call structure were used
   instead of the `while True` loop, given that Claude requested two tools
   in a single response. User's first answer missed the point (described an
   if/elif short-circuit instead). Gave a hint (Project 4 assumed at most
   one `tool_use` block per response); user didn't get there independently,
   so mentor gave the full answer: grabbing only the first tool_use block
   would drop the second tool request entirely, and worse, the Claude API
   requires every `tool_use` block to get a matching `tool_result` — so the
   follow-up call would likely fail with a validation error, not just give
   an incomplete answer.
2. User correctly identified the need to test AI-driven code multiple times
   rather than trusting one run (terminology corrected to "evals" as above).

## Side investigation — FIFA World Cup 2026 hallucination

User noticed the bot claimed the 2026 FIFA World Cup "hasn't happened yet,"
scheduled for "November-December 2026." Mentor searched and confirmed via
Wikipedia and NPR that the real tournament ran June 11-July 19, 2026, and
Spain beat Argentina 1-0 to win it — meaning the bot was wrong on both the
scheduled dates and on whether it had occurred. Used this as a teaching
moment: the bot's code never tells Claude the actual current date, so it has
no way to reason about "has this already happened" for anything near/after
its training cutoff, and defaults to plausible-sounding guesses instead.
Standard fixes (injecting the current date into the system prompt, or giving
the model a search tool) don't exist in this bot, so this is a known,
explained limitation rather than a bug — also written into the README under
"Known limitations."
