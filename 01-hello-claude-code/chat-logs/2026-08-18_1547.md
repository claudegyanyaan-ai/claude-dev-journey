## Step 1 — git init

Mentor explained: git takes snapshots of code over time; `git init` turns a folder into a git-tracked project by creating a hidden `.git` folder. Nothing is "saved" until `git add` + `git commit`.

Instructed:
```
cd "01-hello-claude-code"
git init
```

User initially reported "yes" (ran it) but on follow-up couldn't find a `.git` folder inside `01-hello-claude-code`.

---

## Debugging: git init landed in the wrong folder

Mentor asked user to diagnose first (per teaching rule: ask their theory, give one hint, then the answer). User correctly guessed the `cd` hadn't actually taken effect before `git init` ran.

Diagnosis steps:
1. Ran `dir` in the parent `Claude dev journey` folder — confirmed `01-hello-claude-code` existed with the exact correct name (so a naming/typo mismatch wasn't the cause).
2. Root cause identified: `git init` was likely run in a *different terminal tab/pane* than the one where `cd` was run, so it executed in the parent folder instead.

**Lesson:** PowerShell's prompt always shows the current path (e.g. `PS C:\...\Claude dev journey>`) — check it before running commands, especially when multiple terminal tabs are open.

**Fix applied:**
```
Remove-Item -Recurse -Force .git      # removed the misplaced repo from the parent folder
cd 01-hello-claude-code
git init
```
Confirmed working: `.git` folder now correctly created inside `01-hello-claude-code`.

## Step 4 — .gitignore and .env.example (in progress)

Mentor explained purpose of each file before creation:
- **`.gitignore`** — tells git which files to never track; created *before* anything sensitive exists, so the real API key can never be accidentally committed.
- **`.env.example`** — a template showing the required environment variable, with no real secret, so anyone (including future-you) can copy it to `.env` and fill in their own key.

Content given:

`.gitignore`:
```
.env
__pycache__/
*.pyc
.venv/
venv/
```

`.env.example`:
```
ANTHROPIC_API_KEY=your-api-key-here
```

Next: create both files by hand in VS Code, then run `git status` to confirm git sees them as new/untracked files, before touching a real API key.
