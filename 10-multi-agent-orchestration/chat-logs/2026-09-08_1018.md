## `/ask-network` slash command — first hands-on test

This session was short and single-purpose: exercising a new **project slash
command**, `/ask-network`, that the user had written into
`.claude/commands/ask-network.md` (still untracked at repo root as of this
log). It's the first of this project's "deliberately use a Claude Code
feature hands-on" items (per the 2026-09-07 log's open list) to actually
get built and run.

The command wraps the orchestrator: it takes a networking question as its
argument, confirms the working folder is `10-multi-agent-orchestration`
(the orchestrator, `.venv`, and all three indexes live there, not at repo
root), checks that `ANTHROPIC_API_KEY` is set and that all three indexes
exist under `data/index/{dwdm_osnr,ethernet,ip}/` (each needing
`chunks.json`, `embeddings.npy`, `meta.json`), then runs
`python -m src.orchestrator "<question>"` from that folder using the venv's
Python and prints the output **verbatim** — the three trace lines
(`[orchestrator routed to subagent: ...]`, `[document: ...]`,
`[pages referenced: ...]`) followed by the answer, with no summarizing or
reformatting.

## Run 1 — empty argument, caught early

The command fired once with no question passed. Rather than guess or run
the orchestrator on an empty string, the pre-flight checks were done first
(`.env` present with a real key, `.venv` at `.venv/Scripts/python.exe`, all
three index directories complete) and then the run was stopped with a plain
request for the actual question — matching the command's own instruction to
say so plainly and stop rather than proceed on a missing input.

## Run 2 — "What is noise figure in an EDFA?"

Second call passed a real question. The orchestrator **routed to
`dwdm_osnr`** (correct — EDFA noise figure is squarely optical-amplifier
territory), cited `docs/dwdm_osnr/dwdm_osnr.pdf`, and referenced page
ranges `[[10, 11], [8, 9], [10, 10], [7, 8]]`. The grounded answer came
back complete: the NF formula (`NF = 2nsp[1 - (1/G)]`), the spontaneous
emission factor `nsp = N2/(N2 - Ni)`, the **3 dB quantum limit** at full
inversion, real-world ranges (3.5–6 dB; C-band 3.5–5.5, L-band 4.5–6.5),
and the optimization notes (980 nm first-stage pumping, dual-stage
configs). This is the same question the 2026-09-07 session used to confirm
the widened 1200/300 chunk window had improved `dwdm_osnr`'s answers — so
it doubled as a regression check, and the answer held up.

Two bits of expected startup noise printed to stderr ahead of the trace
lines: a Hugging Face "unauthenticated requests / set `HF_TOKEN`" rate-limit
warning and the `sentence-transformers` weight-loading progress bar. Both
are normal for a cold embedding-model load and not part of the answer; the
command's job is just to pass the real stdout through untouched, which it
did.

## Unit tests — first real run

`pytest` wasn't installed in `.venv` yet. Installed it (pulled in
`iniconfig` and `pluggy` as new transitive deps). First run used the bare
`pytest tests/ -v` command and hit `ModuleNotFoundError: No module named
'src'` on all three files — a known pytest quirk: the `pytest` console-script
entry point doesn't add the current working directory to `sys.path`, so it
can't see the sibling `src/` package. Re-ran as `python -m pytest tests/ -v`
instead (`python -m` does add cwd to `sys.path`), and all 4 tests passed
cleanly in ~24s:

```
tests/test_orchestrator.py::TestClassifyDomain::test_classify_domain_returns_valid_domain PASSED
tests/test_rag_core.py::TestChunkText::test_long_text_splits_with_overlap PASSED
tests/test_rag_core.py::TestChunkText::test_short_text_becomes_one_chunk PASSED
tests/test_subagents.py::TestEthernetSubagent::test_answer_calls_answer_from_index_with_its_own_config PASSED
4 passed in 24.40s
```
